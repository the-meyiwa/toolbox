## 1. Executive Summary

Running `node scripts/anatomy-select.mjs` in a freshly cloned or cleaned workspace currently fails immediately with:
```
Error: ENOENT: no such file or directory, open '.anatomy-src/available.json'
```
This failure occurs because `.anatomy-src/` is in `.gitignore`, so `available.json` was never tracked in version control. Consequently, any automated build, CI pipeline, or developer running the pipeline from scratch encounters an unrecoverable error.

To solve this fundamentally and permanently, this investigation delivers:
1. **Committed Authoritative Manifest**: Exactly 934 binary STL structures from `Kevin-Mattheus-Moerman/BodyParts3D` (1,315,953,756 bytes total) indexed with preferred English anatomical names, sizes, Git blob SHAs, and concept IDs. The complete, validated 247.6 KB JSON artifact is pre-generated at `.agents/explorer_m1_1/proposed_bodyparts3d-available.json` ready for placement at `scripts/data/bodyparts3d-available.json`.
2. **Resilient 3-Tier Discovery Fallback**: An asynchronous discovery mechanism in `scripts/anatomy-select.mjs` that checks:
   - **Tier 1 (Fast Cache)**: `.anatomy-src/available.json` (local working cache).
   - **Tier 2 (Committed Manifest)**: `scripts/data/bodyparts3d-available.json` (authoritative repository source of truth) with automatic seeding of `.anatomy-src/available.json`.
   - **Tier 3 (Dynamic Upstream Fetch)**: Live query to the GitHub Trees API and raw `parts_list_e.txt` if neither local file exists, automatically writing the output to both locations.
3. **Full Downstream Compatibility**: Preserves both `size` and `bytes` properties, ensuring zero regressions for legacy references while fulfilling all interface contracts for Milestones M1 through M5.

## 2. Root Cause Analysis

In `scripts/anatomy-select.mjs` (line 16 and line 102):
```javascript
const SRC = '.anatomy-src';
...
const parts = JSON.parse(fs.readFileSync(path.join(SRC, 'available.json'), 'utf8'));
```

And in `.gitignore` (line 4):
```gitignore
.anatomy-src/
```

Because `.anatomy-src/` is explicitly ignored, `available.json` is not present in Git checkouts. Furthermore:
- The script had no fallback to locate a repository manifest.
- The script had no dynamic discovery capability to query the upstream GitHub repository when unseeded.
- As a result, the pipeline was trapped in a circular dependency: building required `available.json`, but `available.json` could not be generated by any committed script without external intervention.

## 4. Manifest Specification: `scripts/data/bodyparts3d-available.json`

### 4.1 File Location & Tracking
- **Repository Path**: `scripts/data/bodyparts3d-available.json`
- **Git Status**: Tracked in version control (`scripts/` is not in `.gitignore`).
- **File Size**: 247.6 KB (uncompressed JSON, 2-space indented).

### 4.2 Record Schema
Each item in the JSON array adheres strictly to the following specification:

```typescript
interface BodyParts3DAvailablePart {
  id: string;        // Canonical identifier (e.g. "FMA12519" or "BP24")
  name: string;      // Preferred English anatomical name (e.g. "atlas")
  file: string;      // STL filename relative to stl/ directory (e.g. "FMA12519.stl")
  bytes: number;     // Size of the binary STL in bytes (e.g. 483284)
  size: number;      // Exact alias of bytes for backward compatibility with p.size
  sha: string;       // 40-character Git blob SHA-1 from upstream repository
  concept: string;   // FMA or BodyParts3D concept identifier (e.g. "FMA12519")
  conceptId: string; // Alias for concept (e.g. "FMA12519")
  fma: string | null;// Numeric FMA code (e.g. "12519") or null for BP items
}
```

### 4.3 Schema Rationale & Backward Compatibility
1. `id`: Used by `anatomy-build.mjs` as the 3D scene node name (`doc.createMesh(part.id)` / `doc.createNode(part.id)`) and by `anatomy-explorer.js` as the raycasting entity identifier.
2. `name`: Used by `anatomy-select.mjs` for regular expression system classification (`classify(p.name)`).
3. `file`: Canonical filename (`${id}.stl`), establishing explicit asset binding.
4. `bytes` vs `size`: `PROJECT.md` specifies `bytes`, whereas legacy `anatomy-select.mjs` referenced `p.size` on lines 106, 118, 126, and 139. By including both properties with identical values, consumers using either naming convention function without modification or regression.
5. `sha`: Allows future caching layers or integrity verifiers to detect corrupted downloads or upstream changes without re-downloading.
6. `concept` and `conceptId`: Satisfies explicit requirement for concept ID tracking.
7. `fma`: Pre-computes the FMA code (e.g. `"12519"`), directly aligning with `public/anatomy/index.json` schema (`part.id.startsWith('FMA') ? part.id.slice(3) : null`).

## 5. Three-Tier Resilient Discovery Strategy

To ensure high availability across environments (offline development, clean CI runners, fresh checkouts), `scripts/anatomy-select.mjs` must execute a resilient 3-tier discovery hierarchy:

```
                  ┌───────────────────────────────┐
                  │ loadAvailableParts() invoked  │
                  └──────────────┬────────────────┘
                                 │
                 ┌───────────────▼───────────────┐
                 │ Tier 1: Local working cache   │
                 │ .anatomy-src/available.json   │
                 └───────────────┬───────────────┘
                     Exists?     │     Does not exist / invalid
                   ┌─────────────┴─────────────┐
                   ▼                           ▼
        ┌─────────────────────┐   ┌───────────────────────────────┐
        │ Return cached array │   │ Tier 2: Committed manifest    │
        │ (Fastest, 0 IO)     │   │ scripts/data/bodyparts3d-...  │
        └─────────────────────┘   └───────────────┬───────────────┘
                                      Exists?     │     Does not exist / invalid
                                    ┌─────────────┴─────────────┐
                                    ▼                           ▼
                         ┌─────────────────────┐   ┌───────────────────────────────┐
                         │ Seed .anatomy-src/  │   │ Tier 3: Dynamic GitHub Fetch  │
                         │ Return data         │   │ api.github.com + raw URL      │
                         └─────────────────────┘   └───────────────┬───────────────┘
                                                                   │
                                                                   ▼
                                                   ┌───────────────────────────────┐
                                                   │ Write to committed manifest   │
                                                   │ & seed .anatomy-src/ cache    │
                                                   │ Return 934 parts              │
                                                   └───────────────────────────────┘
```

### 5.1 Tier 1: Local Working Cache
- **Path**: `.anatomy-src/available.json`
- **Behavior**: Fast synchronous read if file exists and contains a non-empty array.
- **Purpose**: Preserves developer workflow during local iterative runs without touching disk or network.

### 5.2 Tier 2: Committed Manifest
- **Path**: `scripts/data/bodyparts3d-available.json`
- **Behavior**: Read and parse if Tier 1 is absent.
- **Cache Seeding**: Automatically ensures directory `.anatomy-src/` exists and writes a copy to `.anatomy-src/available.json`.
- **Purpose**: Guarantees zero network calls on clean repository clones, preventing build failures in air-gapped or network-restricted environments.

### 5.3 Tier 3: Dynamic Upstream Fetch
- **Trigger**: Occurs only if neither local file exists (e.g. if the data file was deleted or in an external bootstrap scenario).
- **Step 1 - Fetch Terminology**: Fetches `parts_list_e.txt` via raw GitHub URL (`https://raw.githubusercontent.com/Kevin-Mattheus-Moerman/BodyParts3D/main/assets/BodyParts3D_data/parts_list_e.txt`). This raw endpoint is **not** subject to GitHub API 60 req/hr rate limits.
- **Step 2 - Fetch File Tree**: Queries `https://api.github.com/repos/Kevin-Mattheus-Moerman/BodyParts3D/git/trees/main?recursive=1` with proper headers (`User-Agent: Toolbox-Anatomy-Pipeline`, optional `process.env.GITHUB_TOKEN`).
- **Step 3 - Rate Limit Resilience**: Catches HTTP 403 / 429 and logs a helpful error instructing the developer to set `GITHUB_TOKEN` or restore `scripts/data/bodyparts3d-available.json`.
- **Step 4 - Atomic Cache Seeding**: Writes the assembled 934-part manifest to both `scripts/data/bodyparts3d-available.json` and `.anatomy-src/available.json`.

## 6. Downstream Compatibility & Interface Contracts

### 6.1 Compatibility with `scripts/anatomy-select.mjs`
- `loadAvailableParts()` is an async function called at top-level via `const parts = await loadAvailableParts();`. Because `anatomy-select.mjs` is an ES module (`.mjs`), top-level `await` is natively supported by Node.js.
- Classification loops access `p.name` and `p.size` — both exist on every record.
- Download routine `fetchOne(part)` accesses `part.id` and `part.size` — both exist on every record.

### 6.2 Compatibility with `scripts/anatomy-build.mjs`
- `anatomy-build.mjs` consumes `.anatomy-src/selected.json`, reading `part.id` and `part.name`.
- Because `anatomy-select.mjs` outputs objects spread from `p` (`{ ...p, system }`), `part.id`, `part.name`, `part.system`, and `part.fma` are seamlessly preserved.

### 6.3 Compatibility with `public/anatomy/index.json`
- `index.structures` requires `{ id, name, system, fma }`.
- For FMA items, `fma` is the numeric portion of the ID (e.g. `12519`).
- For BP items, `fma` is `null`.
- Both conventions are verified and consistent with the existing `index.json`.

```javascript
async function fetchPartsFromGitHub() {
  const headers = {
    'User-Agent': 'Toolbox-Anatomy-Pipeline',
    'Accept': 'application/vnd.github.v3+json',
  };
  if (process.env.GITHUB_TOKEN) {
    headers['Authorization'] = `token ${process.env.GITHUB_TOKEN}`;
  }

  // 1. Fetch parts list for English names (via raw URL to avoid API rate limits)
  const rawPartsListUrl = 'https://raw.githubusercontent.com/Kevin-Mattheus-Moerman/BodyParts3D/main/assets/BodyParts3D_data/parts_list_e.txt';
  const nameRes = await fetch(rawPartsListUrl);
  if (!nameRes.ok) {
    throw new Error(`Failed to fetch parts_list_e.txt: HTTP ${nameRes.status} ${nameRes.statusText}`);
  }
  const nameText = await nameRes.text();
  const nameMap = new Map();
  for (const line of nameText.split('\n')) {
    const cols = line.split('\t');
    if (cols.length >= 2) {
      const id = cols[0].replace(/"/g, '').trim();
      const name = cols[1].replace(/"/g, '').trim();
      if (id && name) nameMap.set(id, name);
    }
  }

  // 2. Fetch Git tree for STLs
  const treeUrl = 'https://api.github.com/repos/Kevin-Mattheus-Moerman/BodyParts3D/git/trees/main?recursive=1';
  const treeRes = await fetch(treeUrl, { headers });
  if (!treeRes.ok) {
    if (treeRes.status === 403) {
      throw new Error(`GitHub API rate limit exceeded (HTTP 403). Set GITHUB_TOKEN environment variable or ensure ${COMMITTED_MANIFEST} exists.`);
    }
    throw new Error(`Failed to fetch GitHub tree: HTTP ${treeRes.status} ${treeRes.statusText}`);
  }
  const treeJson = await treeRes.json();
  if (!treeJson.tree || !Array.isArray(treeJson.tree)) {
    throw new Error('Invalid response structure from GitHub tree API');
  }

  const stlPrefix = 'assets/BodyParts3D_data/stl/';
  const manifest = [];
  for (const entry of treeJson.tree) {
    if (entry.type === 'blob' && entry.path.startsWith(stlPrefix) && entry.path.endsWith('.stl')) {
      const filename = path.basename(entry.path);
      const id = filename.replace(/\.stl$/i, '');
      const name = nameMap.get(id);
      manifest.push({
        id,
        name: name || id,
        file: filename,
        bytes: entry.size,
        size: entry.size,
        sha: entry.sha,
        concept: id,
        conceptId: id,
        fma: id.startsWith('FMA') ? id.slice(3) : null,
      });
    }
  }

  manifest.sort((a, b) => a.id.localeCompare(b.id));
  return manifest;
}

async function loadAvailableParts() {
  const localCachePath = path.join(SRC, 'available.json');

  // Tier 1: Local cache in .anatomy-src/available.json
  if (fs.existsSync(localCachePath)) {
    try {
      const data = JSON.parse(fs.readFileSync(localCachePath, 'utf8'));
      if (Array.isArray(data) && data.length > 0) {
        console.log(`[Discovery] Loaded ${data.length} parts from local cache (${localCachePath})`);
        return data;
      }
    } catch (err) {
      console.warn(`[Discovery] Warning: Failed to parse ${localCachePath}: ${err.message}`);
    }
  }

  // Tier 2: Committed manifest in scripts/data/bodyparts3d-available.json
  if (fs.existsSync(COMMITTED_MANIFEST)) {
    try {
      const data = JSON.parse(fs.readFileSync(COMMITTED_MANIFEST, 'utf8'));
      if (Array.isArray(data) && data.length > 0) {
        console.log(`[Discovery] Loaded ${data.length} parts from committed manifest (${COMMITTED_MANIFEST})`);
        fs.mkdirSync(SRC, { recursive: true });
        fs.writeFileSync(localCachePath, JSON.stringify(data, null, 2));
        return data;
      }
    } catch (err) {
      console.warn(`[Discovery] Warning: Failed to parse ${COMMITTED_MANIFEST}: ${err.message}`);
    }
  }

  // Tier 3: Dynamic fetch from GitHub API
  console.log('[Discovery] No local manifest found. Fetching catalog dynamically from GitHub upstream...');
  const data = await fetchPartsFromGitHub();

  fs.mkdirSync(SRC, { recursive: true });
  fs.writeFileSync(localCachePath, JSON.stringify(data, null, 2));

  const manifestDir = path.dirname(COMMITTED_MANIFEST);
  fs.mkdirSync(manifestDir, { recursive: true });
  fs.writeFileSync(COMMITTED_MANIFEST, JSON.stringify(data, null, 2));

  console.log(`[Discovery] Successfully fetched and cached ${data.length} parts to ${localCachePath} and ${COMMITTED_MANIFEST}`);
  return data;
}

/* ---------------- main ---------------- */

const parts = await loadAvailableParts();
```
